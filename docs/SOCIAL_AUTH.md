# Google, VK ID и Яндекс ID

Интеграции реализованы в backend и Android. Реальные входы требуют регистрации приложений у провайдеров; без ключей кнопка сообщает, что способ ещё не настроен. Ни OAuth-секреты, ни токены провайдеров не включаются в APK и Git.

Текущая демонстрация, 15 ноября 2026: **Яндекс ID настроен и проверен настоящим входом**, включая возврат через постоянную страницу, выдачу сессии и доступ к API. Проверочная сессия отозвана после теста. **Google настроен** в отдельном проекте Habit Tracker: выполнены реальная авторизация Google и возврат в backend. При первом входе защита от объединения по email корректно потребовала явную привязку; пользователь выполнил её в приложении. На сервере подтверждены Google-идентичность в прежнем аккаунте телефона, сохранность двух записей и входа по паролю. Google пока работает в тестовом режиме с аккаунтом владельца в списке тестовых пользователей. VK ID не настроен: доступ к кабинету блокирует политика инструмента браузера. Это ограничение текущей настройки, а не доказательство несовместимости провайдера.

## Как устроен вход

Android открывает системный браузер на странице провайдера. Backend хранит случайный state, PKCE verifier и привязку к попытке на 5 минут. Телефон получает результат только с отдельным случайным ключом. Код и результат используются однократно. При перезапуске приложения незавершённый вход нужно повторить.

Успешный вход выдаёт собственную сессию Habit Tracker. Access token провайдера используется сервером только для получения профиля. Существующие аккаунты по совпадению email **не объединяются**. Сначала войди прежним способом, затем выбери **Настройки → Способы входа → Привязать**. Чужая уже привязанная идентичность отклоняется. Отзыв сессии до завершения привязки отменяет её.

## Постоянные Redirect URI

Страницы возврата размещены в GitHub Pages этого проекта и пересылают одноразовый код текущему backend, используя опубликованный указатель адреса. PKCE verifier и client secret остаются только на backend. GitHub, как HTTPS-посредник страницы возврата, технически получает URL с одноразовым кодом; без серверных ключей он недостаточен для получения сессии.

Зарегистрируй адреса **точно, включая завершающий `/`**:

| Провайдер | Redirect URI |
| --- | --- |
| Google | `https://narysh.github.io/habit-tracker/auth/social/google/callback/` |
| VK | `https://narysh.github.io/habit-tracker/auth/social/vk/callback/` |
| Яндекс | `https://narysh.github.io/habit-tracker/auth/social/yandex/callback/` |

Это веб-серверный OAuth Authorization Code flow. Клиентские секреты Google и Яндекса хранятся на backend; VK использует PKCE с `device_id` и без client secret. Нужны только права на базовый профиль/email, без доступа к контактам, переписке и файлам.

## Настройка владельцем

1. Google: создай OAuth-клиент типа **Web application** в Google Cloud Console, настрой consent screen и тестовых пользователей, добавь Google Redirect URI. Scopes: `openid email`. Если кабинет требует подтверждения домена или дополнительные проверки, выполни их до включения способа для всех пользователей. [Официальная инструкция Google](https://developers.google.com/identity/protocols/oauth2/web-server).
2. VK: создай приложение в кабинете VK ID, разреши веб-авторизацию с указанным Redirect URI. Нужен App ID; scopes: `vkid.personal_info email`. [Официальный VK ID SDK и описание Code/PKCE](https://github.com/VKCOM/vkid-web-sdk/blob/master/src/auth/auth.ts).
3. Яндекс: создай OAuth-приложение с веб-платформой и указанным Redirect URI, разреши `login:email login:info`. Получи Client ID и Client secret. [Регистрация у Яндекса](https://yandex.ru/dev/id/doc/en/register-client), [Code + PKCE](https://yandex.ru/dev/id/doc/ru/codes/code-url).

Создай **локально** `.local/social.env`:

```dotenv
GOOGLE_CLIENT_ID=значение_из_кабинета
GOOGLE_CLIENT_SECRET=значение_из_кабинета
VK_CLIENT_ID=значение_из_кабинета
YANDEX_CLIENT_ID=значение_из_кабинета
YANDEX_CLIENT_SECRET=значение_из_кабинета
SOCIAL_CALLBACK_BASE=https://narysh.github.io/habit-tracker
```

Добавляй только готовые пары значений, без заглушек. Не присылай секреты в чат. Затем останови backend `scripts/Stop-Backend.ps1` и снова запусти `scripts/Start-Internet.ps1`. Настроенные кнопки активируются после следующего обращения приложения к серверу. При отдельном размещении проекта замени callback base в окружении и настройках всех провайдеров.

## Что проверено автоматически

Проверены state, два отдельных PKCE-ключа, защита повторного кода/результата, отмена, отзыв сессии привязки, изоляция аккаунтов и запрет объединения по email. Сеть провайдера в автоматических тестах заменена тестовым адаптером. Яндекс дополнительно проверен настоящим OAuth-входом и доступом к защищённому API. Для Google проверены настоящая авторизация и явная привязка к прежнему аккаунту; отдельный повторный вход после привязки пока не проверялся. Реальный вход VK остаётся непроверенным; успешные локальные тесты не заменяют эту проверку.
