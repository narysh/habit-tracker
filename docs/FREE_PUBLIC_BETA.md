# Бесплатный публичный демо-стенд

Инструкция создаёт отдельный тестовый backend на Render Free, базу PostgreSQL и закрытое объектное хранилище вложений в Neon. Она не переносит существующую базу и не включает реальные аккаунты. У Render есть бесплатный web service без карты; у Neon есть бесплатный план и совместимое с S3 объектное хранилище. Проверь актуальные лимиты провайдеров перед запуском: [Render Free](https://render.com/docs/free), [тарифы Neon](https://neon.com/pricing), [Neon Object Storage](https://neon.com/blog/building-neon-object-storage).

Это стенд для демонстрации, не production-хостинг. Render останавливает бесплатный сервис после 15 минут без входящих запросов, а запуск после простоя обычно занимает около минуты. Его файловая система временная, поэтому PostgreSQL, файлы и ключ подписи вынесены во внешние сервисы. Бесплатные лимиты или правила провайдеров могут приостановить сервис. Не используй рабочий аккаунт и важные данные.

## 1. Создай отдельное хранилище данных в Neon

1. Создай бесплатный Neon-проект и базу для демо.
2. Скопируй connection string с SSL из панели Neon. Он понадобится как `DATABASE_URL`.
3. Создай приватный S3-совместимый bucket в Neon Object Storage и credentials с доступом к нему. Публичный доступ bucket не включай.
4. Сохрани endpoint и пару ключей для `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`; регион укажи `auto`.

Храни секреты в менеджере переменных окружения Render. Не добавляй их в GitHub, README, сообщения или Android-приложение.

## 2. Создай постоянную идентичность сервера

Из корня проекта в PowerShell выполни:

```powershell
pwsh -File .\scripts\New-HostedConnectionKeys.ps1
```

Скрипт создаст два значения в `.local/hosted-connection-keys.env`. Этот путь игнорируется Git. Скопируй значения в переменные Render `CONNECTION_PRIVATE_KEY_BASE64` и `CONNECTION_PUBLIC_KEY_BASE64`. Не публикуй и не пересоздавай их после запуска: Android использует открытый ключ для проверки подлинности сервера.

## 3. Подготовь ветку и Blueprint

1. Убедись, что изменения с `deployment/render-public-beta.yaml` уже находятся в выбранной ветке публичного `narysh/habit-tracker`.
2. В Render открой **New → Blueprint**, подключи репозиторий и выбери нужную ветку.
3. В поле **Blueprint Path** укажи `deployment/render-public-beta.yaml`. Render поддерживает пользовательский путь Blueprint-файла: [документация](https://render.com/docs/infrastructure-as-code).
4. До создания проверь, что Blueprint создаёт только один Web Service с планом Free. В этом файле нет Render PostgreSQL, платных инстансов и автодеплоя.
5. Создай Blueprint. На запрос значений укажи `DATABASE_URL`, `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` и оба ключа подписи из локального файла.

Если включаешь вход через Google или Яндекс, в той же форме укажи `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `YANDEX_CLIENT_ID` и `YANDEX_CLIENT_SECRET`. Это секреты backend: используй значения из локального `.local/social.env`, не добавляй их в GitHub и не вставляй в этот документ. `SOCIAL_CALLBACK_BASE` уже задан публичным адресом GitHub Pages. Провайдер без настроенного client ID останется отключён. `VK_CLIENT_ID` добавляй после регистрации VK ID-приложения; его сейчас нет.

Остальные настройки задаются файлом: включён публичный MCP, `MCP_CLIENT_SECRET` генерирует Render, OAuth callback — `https://chatgpt.com/connector_platform_oauth_redirect`, а Android URL приложение берёт из выданного Render адреса. Секреты будут доступны только серверу.

Для уже существующего Render-сервиса `sync: false` значения из Blueprint автоматически не устанавливаются: добавь их через **Environment** вручную, если соцвход ещё не настроен.

## 4. Проверь запуск до подключения ChatGPT

В Render дождись успешного deploy и статуса `Live`. Открой выданный HTTPS-адрес:

- `/health` должен вернуть `status: ok`;
- `/readyz` должен вернуть `status: ok` после проверки PostgreSQL и bucket;
- `/.well-known/oauth-authorization-server` должен вернуть OAuth metadata;
- `/mcp` без OAuth-токена не должен раскрывать записи.

Если `/readyz` недоступен, сначала проверь Render logs и значения внешней базы, приватного bucket и пары ключей. Не включай public-read для исправления ошибки доступа.

После того как backend действительно запущен, можно настроить URL для тестового Android APK и приватного подключения ChatGPT через веб. Этот стенд — только демо. Произвольный собственный MCP нельзя вручную подключить из мобильного ChatGPT; для прямых команд с телефона нужен прошедший проверку плагин из публичного каталога. Каталог доступен на мобильных устройствах, но наличие и функции конкретного плагина зависят от аккаунта, тарифа, региона и рабочего пространства. Публикация Habit Tracker и мобильная проверка ещё не выполнены. До этого мобильный запасной путь — явное **Поделиться → Habit Tracker**.

## 5. Эксплуатация и очистка

- Первый запрос после простоя может ждать около минуты; Android ждёт ответ до 90 секунд. Если Render ещё запускается и запрос истёк, WorkManager повторит фоновую синхронизацию.
- Бесплатный сервис может перезапускаться и исчерпать месячные лимиты. Не маскируй остановку искусственными keep-alive запросами.
- У бесплатного Render Postgres срок хранения ограничен, поэтому эта инструкция намеренно использует отдельный Neon проект. Проверь лимиты Neon и не полагайся на этот стенд как на резервную копию.
- При остановке демо удали Blueprint-managed Web Service в Render и отдельно удали тестовый Neon-проект/bucket, если данные больше не нужны.
- Не направляй рабочий Android-клиент на демо без отдельного переноса данных, резервной копии и проверки восстановления.
