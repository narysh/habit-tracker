# Сборка Android для распространения

Релизное приложение подключается к заранее заданному серверу по HTTPS. Релизный APK/AAB нельзя собрать без стабильного backend origin и постоянного ключа подписи: это предотвращает случайную выдачу пользователям тестовой или неподписанной сборки. Временные HTTPS-туннели для релизного адреса запрещены. Пользователь устанавливает APK и входит или регистрируется. Сертификат проверяется системным хранилищем Android.

## Подготовка сборки

1. Разверни сервер Habit Tracker с постоянными данными, резервным копированием и мониторингом; проверь его `/readyz` извне. Бесплатный демонстрационный стенд для релизных данных не подходит. Для сборки укажи только origin, например `https://tracker.example.org`.
2. Подготовь постоянный ключ подписи релиза. Сохрани зашифрованную резервную копию ключа. При каждом обновлении используй тот же ключ и увеличивай `versionCode` в `android-app/build.gradle.kts`.
3. Настрой переменные окружения `HABIT_TRACKER_SIGNING_STORE_FILE`, `HABIT_TRACKER_SIGNING_STORE_PASSWORD`, `HABIT_TRACKER_SIGNING_KEY_ALIAS`, `HABIT_TRACKER_SIGNING_KEY_PASSWORD`. Загружай пароли из своего менеджера секретов. `STORE_FILE` принимает абсолютный путь к хранилищу ключа.
4. Собери APK для прямой установки или AAB для магазина.

```powershell
.\gradlew.bat :android-app:assembleRelease :android-app:bundleRelease -PhabitTrackerOrigin=https://tracker.example.org
```

Результаты находятся в `android-app/build/outputs/apk/release` и `android-app/build/outputs/bundle/release`. При пути проекта с кириллицей на Windows Gradle выводит их под `%TEMP%/habit-tracker-<id>/android-app/outputs`.

Проверь подпись `apksigner verify --print-certs` и сравни SHA-256 сертификата с сохранённым отпечатком ключа релиза. Перед выдачей проверь чистую установку, регистрацию и обновление поверх предыдущей версии, подписанной тем же ключом. APK из debug-публикаций имеет другой сертификат. Для проверки релиза на устройстве с debug-версией используй отдельный тестовый телефон или эмулятор.

## Проверка перед выдачей

- Чистая установка на обычном телефоне находит нужный HTTPS-сервер, а регистрация и вход проходят через мобильный интернет.
- Задачи, заметки с файлами и привычки переживают перезапуск в офлайне. После подключения очередь выгружается, файлы открываются, конфликтующие правки можно разрешить.
- Второй аккаунт не видит записи и вложения первого. Истёкшую сессию можно восстановить входом в тот же аккаунт.
- Если релиз обещает ChatGPT, реальный мобильный клиент создаёт задачу и заметку, записи появляются в Android, а отзыв доступа прекращает запись из чата.
- Сервер и база сохраняют данные после перезапуска и обновления. Копия базы и файлов восстанавливается на отдельном хосте.
- Страница поддержки объясняет, как связаться с оператором, экспортировать и удалить данные аккаунта. Пользователю доступна актуальная политика обработки данных.
