# Публичный плагин Habit Tracker

Плагин подключает аккаунт Habit Tracker через OAuth и работает с теми же записями, что и Android после синхронизации. MCP предоставляет чтение задач, заметок, привычек, проектов и истории; создание; редактирование, выполнение и удаление; поиск и план недели. Выбранное вложение передаётся только при отдельном вызове `get_attachment`. Сервер выдаёт только инструменты, разрешённые OAuth-областью: при `tracker:read` инструменты записи не публикуются в каталоге.

## Важное ограничение ChatGPT

По актуальной документации OpenAI собственный MCP подключается в веб-версии ChatGPT в тарифах Business и Enterprise/Edu; у Pro подключение ограничено чтением. Нативные приложения ChatGPT для Android и iOS пользовательские MCP-серверы не поддерживают. На вебе Habit Tracker нужно выбрать для сообщения через `@` или список приложений; выбор относится к этому сообщению, а не автоматически ко всем чатам. Поэтому нельзя обещать, что команда из любого чата мобильного ChatGPT автоматически попадёт в Habit Tracker или что запись через MCP доступна обычному личному аккаунту.

Мобильный обходной вариант — попросить ChatGPT вернуть HTTPS-ссылку «Добавить в Habit Tracker» и нажать её. На Android с проверенным App Link ссылка открывает приложение напрямую; если проверка ещё не прошла, GitHub Pages показывает кнопку **Открыть в Habit Tracker**. Если мобильный клиент не открывает ссылку, отправь выбранный ответ через **Поделиться → Habit Tracker**. Это явное действие пользователя, а не автоматическое чтение переписки. При повторном открытии той же ссылки приложение не создаёт дубликат. [Инструкция по импорту](TASK_LINK.md). Частный Sites-пилот предназначен только владельцу и синтетическим данным; он не заменяет публикацию многопользовательского сервиса.

Источник: [подключение собственных MCP-серверов и доступность ChatGPT](https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt).

## Развёртывание

Для бесплатного публичного демо без карты подготовлен Render Free Blueprint и отдельная схема с PostgreSQL и приватными вложениями Neon. Инструкция, переменные окружения, генерация стабильной идентичности и ограничения описаны в [руководстве публичного демо](FREE_PUBLIC_BETA.md). Это временный тестовый стенд, не хостинг для рабочих данных.

Для тестового сервиса выбрать ветку `codex/public-chatgpt-plugin`, `backend/Dockerfile` с контекстом `/` и публичный HTTP-порт 8081. Базу PostgreSQL подключить по приватному адресу через `JDBC_URL`, `DB_USER`, `DB_PASSWORD`. После выделения публичного адреса установить `PUBLIC_URL` в то же HTTPS-значение без `/mcp`, включить `PUBLIC_CHATGPT_PLUGIN` и проверить `/health`, OAuth discovery и `/mcp`. Публикация требует проверки домена и рабочего OAuth. До миграции реальных аккаунтов нужно отдельно обеспечить постоянное хранение файлов и ключа идентичности, резервное копирование и проверку обновления Android.

Для источника сборки использовать публичный URL `https://github.com/narysh/habit-tracker`. Northflank поддерживает сборку публичного репозитория без подключения GitHub-аккаунта. Dockerfile запускает сборку с `-PbackendOnly=true`, поэтому контейнеру не нужны Android SDK и инструменты сборки APK. [Документация Northflank о публичных репозиториях](https://northflank.com/changelog/support-for-public-repositories).


1. Выделить постоянный HTTPS-домен. Временный адрес демонстрационного туннеля OpenAI не принимает. Настроить TLS-прокси с пересылкой оригинального `Host` и доступом к backend по внутреннему адресу. Следовать [требованиям OpenAI к MCP](https://developers.openai.com/plugins/build/mcp-server), включая mTLS, когда используется публичный прокси перед частным MCP. Сам backend сертификаты клиента не проверяет.
2. Развернуть Ktor и PostgreSQL с постоянными томами для базы и вложений. Настройки есть в `compose.yaml` и `.env.example`: `PUBLIC_URL` равен HTTPS origin, `PUBLIC_CHATGPT_PLUGIN=true`, `BACKEND_BIND=127.0.0.1`. Задать отдельный `MCP_CLIENT_ID=habit-tracker-chatgpt` и случайный секрет в окружении сервера. Применить миграции Flyway с резервной копией базы. В Android указать адрес этого сервера или опубликовать его в настроенном реестре после проверки идентичности сервера.
3. Добавить в `MCP_REDIRECT_URIS` точный OAuth callback из OpenAI Platform. Сервер рекламирует `iss` и поддерживает S256 и `client_secret_post`. Пользователь может подтвердить запрос в уже открытом Android-аккаунте, в том числе если вошёл через Google или Яндекс. Для проверяющих остаётся вход по email и паролю с отдельным демо-аккаунтом.
4. Собрать пакет командой `./scripts/Build-ChatGPT-Plugin.ps1 -Server $origin -DeveloperName $publisher -Website $product -Support $support -PrivacyPolicy $privacy -Terms $terms`. Использовать реальные ссылки и имя подтверждённого разработчика. Скрипт добавляет `/mcp` к адресу сервера и выпускает ZIP с иконкой, метаданными и сценариями проверки. Секрет OAuth вводится в кабинете OpenAI.
5. В [кабинете публикации](https://platform.openai.com/apps-manage) загрузить ZIP в разделе Plugins. Значение `OPENAI_APPS_CHALLENGE` устанавливается по подсказке кабинета; backend возвращает его как обычный текст на `/.well-known/openai-apps-challenge`. После проверки домена связать изолированный демо-аккаунт, выполнить сканирование и заполнить требования к демонстрации и проверке. [Процесс публикации](https://developers.openai.com/plugins/deploy/submission).

В ChatGPT выбрать Habit Tracker и запустить подключение. Скопировать 16-символьный код со страницы согласия, открыть **Habit Tracker → Настройки → Подключить ChatGPT**, проверить код и разрешения для текущего аккаунта. Вернуться в браузер и нажать **Завершить подключение**. Код действует пять минут. Одобрение требует действующей Android-сессии и применяется только к одному OAuth-запросу. Токен ChatGPT выдаётся после завершения в исходном браузере и обмена по PKCE.

Там же отображается статус подключения к аккаунту. **Отключить ChatGPT → Отключить доступ** отзывает токены этого клиента и подтверждённые, но незавершённые запросы подключения. Вход в Android и задачи сохраняются. Пометка о подключении в интерфейсе ChatGPT может сохраняться, пока он не проверит доступ.

В веб-версии ChatGPT и в рабочем пространстве, где разрешены записи, выбрать плагин для сообщения (`@Habit Tracker`) и попросить «Добавь задачу оплатить интернет», затем «Сохрани заметку „Поездка“ с текстом „Взять паспорт“». Чтобы следующее сообщение снова вызывало инструменты, выбери плагин повторно. Проверить задачу и заметку в Android после синхронизации. Во втором аккаунте список задач и заметок должен содержать только его собственные записи. На нативном мобильном ChatGPT этот сценарий недоступен.

Локальная проверка backend: `gradle :backend:test :shared:test`. Сценарий публичного режима использует аккаунт без пароля, подтверждение с Android-сессией и OAuth с PKCE. Он создаёт задачу и заметку через MCP и проверяет их через `/api/v1/sync`, который использует Android. Также проверяются область доступа для записи, защита от повторного выполнения и изоляция аккаунтов.

После облачного развёртывания запусти `python scripts/test_public_plugin.py https://<адрес-сервера>` с `HABIT_SMOKE_CLIENT_SECRET` в локальном окружении. Если OpenAI уже выдал токен проверки домена, добавь `--challenge` с его значением. Скрипт требует доверенный TLS и проверяет метаданные OAuth, создание задач и заметок без дублей, синхронизацию, изоляцию и отзыв доступа. Запускай на отдельном стенде. Скрипт регистрирует два синтетических аккаунта, отзывает их сессии и оставляет данные этих аккаунтов в тестовой базе. Мобильный клиент ChatGPT проверяется отдельно.
