# Habit Tracker в личном плагине ChatGPT

Этот прототип связывает владельца закрытого ChatGPT Site с отдельным тестовым аккаунтом Habit Tracker на Render. После настройки OAuth он передаёт ChatGPT инструменты, разрешённые текущим токеном backend: чтение, создание, изменение, выполнение, удаление, привычки и историю. Сам посредник пропускает только публичный allowlist, а схемы и права берёт из backend. Для рабочего аккаунта используется обычное OAuth-подключение опубликованного MCP-сервера.

## Подготовка

1. Создай отдельный Site через Sites в том же аккаунте ChatGPT, в котором будешь проверять плагин. Выбери закрытую публикацию только для владельца.
2. Укажи точный `project_id` из Sites в `.openai/hosting.json` этого отдельного проекта. `capabilities: ["mcp"]` включает создание связанного плагина. Дополнительный ключ OpenAI API не нужен.
3. В конфигурации среды Sites задай `HABIT_TRACKER_SITE_ORIGIN`. Это HTTPS-адрес проекта Sites без завершающего слеша и пути. Его сообщает Sites при создании проекта. Выполни `npm test` и `npm run build`, затем опубликуй сборку как закрытый Site.
4. Открой главную страницу опубликованного Site в этом же аккаунте. Возьми значение `site_owner_id` из ответа и задай его как `HABIT_TRACKER_SITE_OWNER_ID` в серверной конфигурации Sites. После привязки главная страница возвращает только статус привязки.
5. Получи короткоживущий OAuth access token для синтетического аккаунта через сценарий согласия и PKCE с областями `tracker:read tracker:write`. Установи его в Sites как секрет `HABIT_TRACKER_MCP_ACCESS_TOKEN`. Backend выдаёт токен на **один час**. Обновление токена в этом прототипе ручное. Пароль, секрет OAuth-клиента и refresh token в Sites не передаются.
6. Примени конфигурацию к закрытой публикации. Если настройки среды требуют новой публикации, используй ту же сборку и видимость только для владельца. Установи созданный Sites плагин через **Плагины → Личные → Созданные вами**.

Токен предназначен только для выделенного приложения в [тестовой среде Render](https://habit-tracker-plugin-pilot.onrender.com/health). Укажи при тесте тот же адрес сервера и тот же синтетический аккаунт на Android. Открывай Site в режиме владельца. Секреты задавай через серверные переменные Sites с отметкой **Secret**, вне репозитория и чата.

## Проверка

На телефоне в новом чате выбери личный плагин и попроси создать тестовую задачу и заметку. Проверь подтверждение в ChatGPT, если оно появится, и наличие обеих записей в тестовом аккаунте Android. Доступность личного плагина проверяй в обычном Chat и, отдельно, в Work. Локальные тесты проверяют маршруты Worker и имитацию ответа от MCP.

Мост привязывает вызовы к идентификатору владельца, который сообщает среда Sites, проверяет OAuth-каталог backend и пересылает только явно вызванный инструмент по HTTPS на единственный адрес из исходного кода. OAuth-токен никогда не возвращается клиенту. Удаление и правки сохраняют аннотации и подтверждения, заданные backend; отменённую операцию не вызывай повторно. Вложения не читаются при обычном списке: `get_attachment` доступен отдельно и получает только выбранный id. HTTP 200 на `POST /mcp` означает только, что вызов обработал Worker; ориентируйся на результат Habit Tracker. При истёкшем, отозванном, не настроенном или недоступном подключении запись не подтверждена. При неопределённом результате сохраняй тот же `operation_id` при повторе, чтобы избежать дублей. После проверки отзови доступ ChatGPT в тестовом аккаунте и убери секрет из Sites.
